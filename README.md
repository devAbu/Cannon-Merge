# Cannon Merge

Offline pirate merge-defense game for Android (working title). Portrait, one-handed, touch only, no internet needed.

You sail a ship with a 4x4 cannon deck. Buy cannons, merge two of the same level into a stronger one, and sink the
pirate ships, sharks and the Kraken that attack from both sides. Between waves you repair the hull with coins.

## Rules in 30 seconds
- **Cannon** button buys a level-1 cannon. Tap one cannon, then another of the same level (or drag it) to merge.
- Levels: Cannon > Twin > Mortar (splash) > Flamer (burn) > Frost (slow) > Storm (chain lightning).
- Cannons in the left half of the deck shoot the left side, the right half shoots the right side. Shooting the far
  side works but at 40% fire rate. The red numbers on the screen edges show how many enemies come from each side.
- **Storm** (waves 3, 6, 9): the ship turns 180 degrees and the cannons get shuffled - rearrange quickly.
- **Kraken** boss on waves 5 and 10. 10 waves in this MVP.
- Rewarded buttons (simulated for now): Hint, Undo, bonus Coins, and Revive on the defeat screen.

## Run locally
```
npm install        # only needed for the Android build
npm start          # static server on http://localhost:8080 (open it in your browser's mobile view)
npm run sim        # balance simulation (bots play full runs)
```
The game itself is plain HTML canvas + vanilla JS in `www/`; there is no build step for the web part.

## Build the APK
Every push runs GitHub Actions (`.github/workflows/build-apk.yml`):
1. runs the balance simulation (fails the build if the game becomes impossible/trivial),
2. generates the Capacitor Android project, locks portrait, adds the VIBRATE permission,
3. builds a debug APK signed with the fixed key in `keystore/` (so updates install over old versions).

Download **cannon-merge.apk** from the run's **Artifacts**, or from **Releases** (non-main branches publish a
`Cannon Merge Dev` pre-release that installs next to the main app). The debug key is not for the Play Store.

To build locally: `npm install && npx cap add android && npx cap sync android && cd android && ./gradlew assembleDebug`.

## Where things are
| What | File |
|---|---|
| Game rules, waves, enemies, cannon stats, storm | `www/core.js` (`CANNON`, `EN`, `STORM_WAVES`, `BOSS_WAVES`, `TOTAL_WAVES`) |
| **All UI text** (for translation) | `www/strings.js` |
| **Settings, progress, hull upgrades** (localStorage `cm_save_v1`) | `www/save.js` |
| **Ads** (simulated rewarded video) | `www/ads.js` (`AdService`) |
| Sound (Web Audio, procedural), vibration | `www/audio.js` |
| Art (all drawn in code, pre-rendered sprites) | `www/gfx.js` |
| Screens, input, effects | `www/main.js` |
| Balance bots | `tools/sim.js` |

Settings (music / effects / vibration) are in the pause menu and on the main menu under **Settings**.

## Swapping in real AdMob later
Only `www/ads.js` talks about ads. The game calls `AdService.status(placement)`, `AdService.show(placement, onReward)`,
`AdService.update()` and `AdService.isBusy()` with the placements `hint`, `undo`, `bonus`, `revive`. Replace the bodies of
`init()` / `show()` with the AdMob plugin calls and call `onReward` when the SDK reports the reward. Nothing else changes.
No banners, no forced ads.

## Art and audio
Everything is original and generated by code (shapes, gradients, particles, WebAudio). No third-party assets.
